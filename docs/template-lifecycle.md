# 에이전트 지침 템플릿 수명주기

이 문서는 공용 에이전트 지침을 다른 저장소에 도입하고 프로젝트에 맞게 초기화한 뒤 안전하게 검증·업데이트하는 기준을 정의합니다.

## 대상 독자

- 이 템플릿을 새 저장소나 기존 저장소에 도입하는 개발자
- 조직의 공용 에이전트 기준선을 유지하는 관리자
- 프로젝트 전용 지침과 공용 기준선의 변경을 검토하는 개발자

## 목표

- 공용 기준선과 프로젝트 전용 규칙의 소유권을 분리합니다.
- 기존 프로젝트 파일과 설정을 덮어쓰지 않고 템플릿을 도입할 수 있게 합니다.
- 지침 검증이 대상 프로젝트의 무관한 소스 파일을 검사하거나 변경하지 않게 합니다.
- 프로젝트 초기화의 완료 여부를 관찰 가능한 조건으로 판단할 수 있게 합니다.
- 기준선 버전과 출처를 기록해 후속 업데이트를 비교할 수 있게 합니다.
- 단일 저장소, 모노레포, 여러 에이전트 도구가 함께 있는 환경의 지원 경계를 설명합니다.

## 범위

이 저장소가 관리하는 템플릿 자산은 다음과 같습니다.

- 루트 `AGENTS.md`
- `agents/common/` 공용 지침
- `agents/project/` 프로젝트 전용 지침 영역
- `docs/`의 템플릿 운영 문서
- `tools/validate_instructions.py`와 회귀 테스트
- 지침 검증용 GitHub Actions 워크플로
- `.editorconfig`, `.gitattributes`, `.gitignore`의 템플릿 관련 항목
- 템플릿 원본의 기준선 버전과 변경 이력

## 제외 범위

- 특정 프로그래밍 언어, 프레임워크 또는 디렉토리 구조 강제
- 대상 프로젝트의 기존 문서·Git 설정·CI 구성 자동 덮어쓰기
- 대상 프로젝트의 소스 코드와 일반 문서에 대한 포맷 검사
- 특정 에이전트 제품만의 독점 기능을 공통 동작으로 가정
- 기준선 업데이트의 자동 병합 또는 충돌 자동 해결
- 사용자가 승인하지 않은 배포, 게시 또는 외부 저장소 변경

## 주요 결정

### 도입 방식

템플릿은 파일을 무조건 덮어쓰는 설치 프로그램을 제공하지 않습니다. 도입자는 템플릿 자산을 대상 저장소와 비교하고, 기존 파일의 책임과 설정을 보존하면서 필요한 항목을 병합합니다.

루트 진입 문서에는 필수 자산, 선택 자산, 충돌 확인 지점과 초기 검증 절차를 제공합니다.

### 공용 기준선과 프로젝트 규칙

`agents/common/`은 기준선에서 관리하고 일반 프로젝트 작업 중에는 직접 수정하지 않습니다. 프로젝트의 기술, 명령, 구조, 용어와 공용 기본값의 명시적 예외는 `agents/project/`에 기록합니다.

프로젝트가 공용 기준선 자체의 변경을 필요로 하면 먼저 재사용 가능한 공통 문제인지 판단합니다. 프로젝트에만 필요한 차이는 공용 파일을 포크하지 않고 프로젝트 지침으로 유지합니다.

### 검증 범위

검증기는 대상 저장소에서 지침 체계가 계속 소유하는 파일만 검사합니다. 대상 프로젝트의 루트 README, 버전·변경 이력, 일반 소스, 생성물과 무관한 문서는 검사하지 않습니다.

검증 대상은 명시적인 관리 경로와 파일 목록으로 결정합니다. Git 추적 여부나 저장소 전체 재귀 탐색을 지침 파일의 소유권 대신 사용하지 않습니다.

### 기준선 버전과 업데이트

루트 `VERSION`은 현재 기준선 버전을 Semantic Versioning 형식으로 기록합니다.

- 주요 버전: 기존 프로젝트 지침의 의미나 적용 방식에 호환되지 않는 변경
- 부 버전: 호환되는 새 지침, 검사 또는 운영 기능
- 패치 버전: 의미를 유지하는 수정, 설명 보완 또는 결함 수정

대상 프로젝트는 템플릿 원본의 기준선 버전과 출처를 전용 지침 인덱스에 기록합니다. 템플릿 원본의 `VERSION`과 `CHANGELOG.md`는 비교 자료이며 대상 저장소에 복사할 필요가 없습니다. 업데이트할 때는 현재 프로젝트의 `agents/project/`를 보존하고 공용 기준선·검증 도구·운영 문서의 차이를 검토합니다.

### 호환성

이 템플릿은 저장소 루트의 `AGENTS.md`를 읽고 그 지시를 따를 수 있는 에이전트를 기본 대상으로 합니다. 자동 발견, 하위 디렉토리 지침의 우선순위와 다른 에이전트 전용 파일의 결합 방식은 각 도구의 기능이므로 별도로 확인해야 합니다.

모노레포에서는 루트 공용 기준선이 저장소 전체에 적합한 경우에만 그대로 사용합니다. 패키지별 규칙은 도구가 지원하는 범위 지정 방식이나 명시적으로 구분된 프로젝트 지침에 두고, 서로 다른 패키지 규칙을 하나의 전역 규칙으로 합치지 않습니다.

## 초기화 완료 조건

복제된 기준선의 프로젝트 초기화는 다음 조건을 모두 충족할 때 완료됩니다.

- `docs/README.md`가 템플릿이 아니라 실제 프로젝트의 목적과 문서 위치를 설명합니다.
- `agents/project/README.md`가 프로젝트 목적, 주요 사용자와 등록된 프로젝트 지침을 설명합니다.
- 확인 가능한 실행·빌드·테스트·검사 명령과 중요한 환경 제약이 필요한 프로젝트 지침에 기록되어 있습니다.
- 프로젝트 전용 규칙이 없다면 조사 결과 추가할 규칙이 없다는 점이 인덱스에 명확합니다.
- 기존 지침, 문서, Git 설정과 CI 구성의 충돌을 검토했습니다.
- 도입한 기준선 버전과 출처가 기록되어 있습니다.
- 지침 검증기와 회귀 테스트가 통과합니다.

## 업데이트 절차

1. 현재 작업 트리와 프로젝트 전용 변경을 확인합니다.
2. 현재 기준선 버전과 가져올 기준선의 `VERSION` 및 `CHANGELOG.md`를 비교합니다.
3. `AGENTS.md`, `agents/common/`, 검증 도구와 템플릿 운영 문서의 변경을 검토합니다.
4. `agents/project/`와 실제 프로젝트 문서는 자동 교체하지 않습니다.
5. 기존 `.editorconfig`, `.gitattributes`, `.gitignore`와 CI 파일은 파일 단위로 덮어쓰지 않고 관련 항목만 병합합니다.
6. 호환되지 않는 공용 규칙이 있으면 프로젝트 예외로 유지할 수 있는지 판단하고, 공용 안전·권한 경계는 약화하지 않습니다.
7. 지침 검증기와 회귀 테스트를 실행합니다.
8. 프로젝트에 기록된 기준선 버전과 변경 영향을 갱신합니다.

## 완료 기준

- 검증기가 관리 대상 파일만 검사하고 이 동작을 회귀 테스트로 보장합니다.
- 검증기의 주요 검사 분기와 Windows 줄바꿈 사례에 회귀 테스트가 있습니다.
- 루트 문서에서 도입, 초기화, 업데이트, 호환성과 제한 사항을 찾을 수 있습니다.
- 프로젝트 지침 예시가 실제 지침으로 오인되지 않는 위치에 제공됩니다.
- 기준선 버전과 변경 이력이 저장소에 존재합니다.
- 공용·프로젝트 지침 인덱스와 CI가 변경된 구조를 정확히 반영합니다.
