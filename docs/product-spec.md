# PreCTG 제품 명세

이 문서는 대회 제안서에 삽입할 PreCTG MVP의 목적, 범위, 참여자 역할과 완료 기준을 정의합니다.

## 1. 프로젝트 맥락

### 1.1 대회

- 대회명: 2026 K-Health 미개방 의료데이터 활용 경진대회
- 주제: K-Health 미개방 의료데이터를 활용한 분석 및 국민 건강 기여 아이디어 제안
- 대회 기간: 2026년 7월 13일~11월 27일
- 예선 제출: 2026년 8월 14일 16:00까지 아이디어 제안서 PDF, 30쪽 이내
- 본선: 상위 15개 팀이 선택한 데이터 제공기관의 의료데이터안심존에서 실제 데이터를 분석하고 결과보고서와 발표자료를 제출
- 예선 평가: 시의성, 실현성, 참신성, 파급성
- 운영 제약: 원본 데이터 반출 불가, 결과물 반출 심의 필요, 폐쇄망에서 인터넷 및 임의 패키지 설치 제한

기획안은 평가 항목을 시의성 20점, 실현성 30점, 참신성 30점, 파급성 20점으로 구성하고 있다. 공식 공지 변경 가능성이 있으므로 제출 직전 대회 페이지와 게시판을 다시 확인한다.

### 1.2 활용 데이터

공식 활용 데이터셋은 AIHub의 「태아 심박동 모니터링 데이터」이다. 이 데이터는 분만 중 태아 심박동(FHR), 자궁 수축(TOCO), CTG 이미지, 태아 상태 및 이상 시점 라벨, 산모·태아 EMR 메타데이터로 구성된다.

현재 원본 데이터와 동일 구조의 샘플 파일은 확보하지 못했다. 예선 MVP는 공개된 메타데이터 구조와 공신력 있는 근거를 토대로 생성한 합성 테스트 데이터만 사용한다. 실제 데이터 학습과 임상 성능 평가는 본선 진출 후 의료데이터안심존에서 수행하는 별도 단계다.

## 2. 명칭과 역할

| 명칭 | 의미 | 이 저장소에서의 역할 |
|---|---|---|
| 디버그랩 | 3인 경진대회 팀명이며 현재 아이디어의 임시 프로젝트명 | 대외 팀 식별 |
| PreCTG | 이번 대회를 위해 구현하는 MVP 모델·애플리케이션 이름 | 이 저장소의 제품명 |
| RiskGate | 팀원 1인이 과거 다른 의료 ML 대회에서 구현한 프로젝트 | 구조와 구현 경험을 참고하는 선행 프로젝트 |

세 명의 팀원 중 두 명은 아이디어 제안서를 구체화하고, 한 명은 제안서에 실행 예시로 삽입할 PreCTG MVP를 구현한다. 현재 저장소의 직접 목표는 제안서 문구 작성이 아니라 PreCTG 구현과 기능 증거 생성이다.

## 3. 문제 정의

분만 중 태아 상태 악화는 신속한 관찰과 대응이 중요하지만 CTG 판독은 숙련도와 지속적인 관찰이 필요하다. 야간·휴일 또는 분만 인프라가 부족한 의료기관에서는 이러한 부담이 더 커질 수 있다.

기존 데이터셋과 기본 모델은 현재 CTG 상태 분류 또는 이미지 내 이상 시점 탐지에 초점을 둔다. PreCTG는 정보를 얻을 수 있는 시점을 분리해 다음 질문을 단계적으로 다룬다.

1. 분만 전 EMR만으로 더 면밀한 관찰이 필요한 위험 요인이 있는가?
2. 분만 초기 관찰 구간에서 CTG 특징은 어떤 범주와 근거를 보이는가?
3. 현재까지 허용된 정보로 이후 응급 라벨과 관련된 위험 신호를 얼마나 강하게 보이는가?

## 4. 제품 목표

PreCTG MVP는 AIHub 메타데이터와 호환되는 입력을 받아 다음 결과를 한 번의 처리 흐름으로 제공해야 한다.

- 0단계: 분만 전 EMR 기반 위험 점수, 위험군과 근거
- 1단계: 초기 CTG 특징 기반 규칙 판정과 근거
- 2단계: LightGBM 기반 응급 관련 위험 확률과 시연용 경보 등급
- 공통: 입력 완전성, 누락 필드, 사용한 입력 시점과 합성 데이터 경고

제품의 핵심 가치는 높은 숫자 성능이 아니라 단계별 정보 축적, 데이터 누수 방지, 설명 가능한 결과와 실제 데이터로 교체 가능한 처리 계약을 작동하는 코드로 보여주는 데 있다.

## 5. 사용자와 사용 흐름

### 5.1 주 사용자

- 예선 제안서를 평가하는 심사위원
- 팀 내부의 기획·모델 개발 담당자
- 본선에서 실제 데이터로 파이프라인을 재학습·검증할 분석자

MVP는 의료 현장 배포 제품이 아니며 환자, 보호자 또는 의료진의 실제 진료에 사용하지 않는다.

### 5.2 대표 흐름

1. 사용자가 합성 환자 사례를 선택하거나 AIHub 호환 JSON/CSV 입력을 제공한다.
2. 시스템이 필드 타입, 코드값, 허용 범위와 결측을 검증한다.
3. 분만 전 정보만으로 0단계 위험 점수와 근거를 계산한다.
4. 초기 CTG 특징으로 1단계 범주와 근거를 계산한다.
5. 허용된 입력 특성만 LightGBM에 전달해 2단계 위험 확률을 계산한다.
6. 통합 경보 등급, 단계별 변화, 주요 근거와 입력 완전성을 화면과 JSON으로 표시한다.
7. 모든 결과에 기능 시연용 합성 데이터라는 경고를 표시한다.

## 6. 기능 요구사항

### 6.1 입력과 검증

- AIHub 공개 메타데이터의 필드명과 코드 체계를 가능한 한 그대로 수용한다.
- 사용자 입력과 파일 입력은 동일한 내부 스키마로 정규화한다.
- 알 수 없는 코드, 허용 범위 밖 수치, 필수값 누락을 명시적으로 보고한다.
- `9999`와 같은 원본의 미상 코드는 실제 수치로 학습하지 않고 결측 상태로 변환한다.
- 동일 산모 또는 동일 태아 식별자가 존재할 경우 데이터 분할 그룹으로 사용할 수 있게 보존한다.

### 6.2 단계별 판단

- 0단계는 분만 전에 알 수 있는 EMR만 사용한다.
- 1단계는 사전에 확정한 초기 관찰 구간 안의 CTG 특징만 사용한다.
- 2단계는 입력 시점 이후에 생성되는 결과 변수를 입력 특성으로 사용하지 않는다.
- 모든 규칙 기반 결과는 적용된 규칙과 입력값을 함께 반환한다.
- ML 결과는 확률, 시연용 등급, 모델 버전과 사용 특성 집합을 반환한다.

### 6.3 결과와 설명

- 결과는 기계 판독용 JSON과 사람용 화면에서 동일한 의미를 가져야 한다.
- `model_confidence`와 `data_completeness`를 혼용하지 않는다. 합성 데이터 단계에서는 실제 모델 신뢰도를 보증하지 않는다.
- 설명은 모델이 실제로 사용한 입력과 규칙만 인용한다.
- 결과 화면에는 진단·처방 도구가 아니며 합성 데이터 기반 기능 시연이라는 경고를 항상 표시한다.

## 7. 비기능 요구사항

- 로컬 CPU 환경에서 학습과 추론이 가능해야 한다.
- 인터넷이 없는 안심존으로 이동할 수 있도록 클라우드 API나 외부 런타임 호출에 의존하지 않는다.
- 동일한 코드, 구성과 난수 시드로 합성 데이터 및 모델 산출물을 재현할 수 있어야 한다.
- 의료 데이터 또는 식별 정보를 로그, 원격 서비스, 저장소에 노출하지 않는다.
- 모델 산출물에 생성 코드 버전, 스키마 버전, 특성 목록과 난수 시드를 기록한다.

## 8. 제외 범위

- 실제 환자에 대한 진단, 처치 권고 또는 임상 의사결정 자동화
- 합성 데이터 성능을 실제 데이터 성능으로 일반화하는 주장
- CTG 원본 이미지 또는 연속 파형에서 특징을 자동 추출하는 딥러닝 모델
- 병원 EMR·분만감시장치와 실제 연동
- 클라우드 배포, 사용자 인증, 다기관 운영과 규제 승인
- 모바일·웨어러블·재택 모니터링 구현

이 항목들은 향후 확장 가능성으로 설명할 수 있지만 현재 MVP의 완료 조건에는 포함하지 않는다.

## 9. MVP 완료 조건

아래 제품 수준 조건과 함께 `mvp-delivery-plan.md`의 Gate 0~7 및 최종 완료 기준선을 모두 충족해야 한다.

- AIHub 호환 예시 JSON 또는 CSV를 검증하고 내부 스키마로 변환할 수 있다.
- 대표 정상·경계·고위험·결측 사례에서 0단계와 1단계 규칙 결과가 기대값과 일치한다.
- 합성 학습 데이터로 LightGBM 모델을 학습·저장·불러오기·추론할 수 있다.
- 결과에서 사후 변수와 라벨이 입력 특성에 포함되지 않았음을 자동 검사한다.
- CLI에서 전체 흐름을 한 번의 명령으로 실행할 수 있다.
- Streamlit 화면에서 단계별 결과, 근거, 입력 완전성과 경고를 확인할 수 있다.
- 50,000건 이상의 합성 데이터를 고정 시드로 생성하고 스키마·분포·논리 제약 검사를 통과한다.
- 테스트 데이터 성능이 임상 성능이 아니라는 제한이 README, 화면과 결과 보고에 일관되게 표시된다.
- 처음 보는 팀원이 별도 설명 없이 대표 사례를 선택해 결과를 이해하는 흐름을 3분 안에 완료한다.
- 주요 화면폭에서 버튼·문장·결과 영역이 겹치거나 잘리지 않으며 키보드로 필수 흐름을 조작할 수 있다.

## 10. 성공 증거

제안서에 사용할 수 있는 MVP 증거는 다음으로 제한한다.

- 입력부터 결과까지 작동하는 화면 캡처
- 단계별 위험도 변화와 판단 근거 예시
- 정상·경계·고위험 사례의 기능 테스트 결과
- 50,000건 배치 처리 완료 시간과 오류 건수
- 누수 차단 검사와 데이터 유효성 검사 결과

합성 데이터에서 산출한 AUC, F1, 정확도는 디버깅 참고값으로만 다루며 모델 우수성의 증거로 사용하지 않는다.

## 11. 미결정 사항

- 분만 초기 관찰 구간의 정확한 길이와 절단 기준
- 0단계 위험 점수의 최종 임상 근거와 가중치
- AIHub의 `CA`가 어느 시점의 판독인지, 여러 이미지·구간과 환자 식별자의 관계
- `Emergency` 라벨의 정확한 정의와 시간적 기준
- 본선 안심존에 설치된 LightGBM 및 Python 버전과 모델 반입 가능 형식
- 실제 데이터에서 사용할 환자 단위 분할 키와 외부 검증 가능성

이 사항은 공식 데이터 설명서, 샘플 확인 또는 주최 측 답변 없이 추정해 확정하지 않는다.
