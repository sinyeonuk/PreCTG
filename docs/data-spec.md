# PreCTG 데이터 명세

이 문서는 공식 AIHub 데이터와 호환되는 PreCTG 입력 계약, 시간적 누수 경계, 합성 테스트 데이터 생성 및 검증 기준을 정의합니다.

## 1. 데이터 목적과 상태

공식 데이터셋은 AIHub 「태아 심박동 모니터링 데이터」다. 공개 페이지에는 2022년 구축, 2023년 12월 최종 개방, 데이터 유형 PNG, 라벨 형식 JSON으로 기재되어 있다.

현재 PreCTG 저장소에는 공식 원본이나 실제 환자 데이터가 없다. 개발에 사용하는 데이터는 모두 공개된 집계 통계와 임상 근거를 바탕으로 생성한 합성 데이터여야 한다. 파일명, 문서와 화면에서는 `synthetic` 또는 `demo`를 명시해 실제 데이터와 혼동하지 않게 한다.

## 2. 공개 데이터 구성

AIHub 공개 설명 기준 각 구성의 건수는 다음과 같다.

| 구성 | 형식 | 공개 기재 건수 | PreCTG MVP 사용 |
|---|---|---:|---|
| CTG 원본 이미지 | PNG | 24,597 | 미사용 |
| 바운딩박스 이미지 | 이미지 | 24,597 | 미사용 |
| 라벨 데이터 | JSON | 24,597 | 스키마와 코드 참조 |
| EMR 메타데이터 | JSON | 24,597 | 스키마와 분포 참조 |
| 이미지 어노테이션 정보 | JSON | 24,597 | 초기 구간 구조 참조 후보 |

페이지 상단 메타데이터 구조표에는 전체 구축량 49,794건도 별도로 기재되어 있다. 두 집계의 단위 관계는 공개 페이지만으로 확정하지 않고 데이터 설명서 또는 실제 데이터 확인 사항으로 남긴다.

공개 집계 중 합성 데이터의 기본 분포를 정하는 데 참고할 값은 다음과 같다.

- 태아 성별: 남아 52.36%, 여아 47.64%
- 산모 연령대: 10대 0.15%, 20대 10.74%, 30대 76.64%, 40대 12.41%, 50대 이상 0.07%
- 출산 횟수: 0회 54.35%, 1회 34.00%, 2회 9.28%, 나머지 구간은 공개 비율 참조
- 임신 횟수: 1회 40.08%, 2회 33.63%, 3회 15.82%, 나머지 구간은 공개 비율 참조
- CTG 범주: Category 1 72.72%, Category 2와 3 합계 27.28%
- 태아 상태: 비응급 53.71%, 응급 46.29%
- 태아 수: 단태아 83.95%, 다태아 16.05%

이 값은 원본의 공개 집계 재현용 기본값이며, 기능 경로를 충분히 시험하는 별도 균형 시나리오 데이터에는 다른 비율을 사용할 수 있다.

`distribution` 프로필은 현재 구현된 열 가운데 산모 연령대, 임신 1회, 출산 0회, 다태임신과 CTG Category 1 비율을 50,000건에서 각각 ±1%p로 검사한다. 산모 연령은 합성 측정일과 생년월로 표현하며, 임신·출산 횟수는 `출산 횟수 < 임신 횟수` 제약을 지키는 결합분포로 생성한다. 공식 정의를 재현할 수 없는 `Emergency`와 현재 생성하지 않는 출생 후 성별은 분포 검사 대상에서 제외한다.

## 3. 필드 분류

### 3.1 라벨·CTG 특징

| 필드 | 공개 타입 | 의미 또는 코드 | MVP 역할 |
|---|---|---|---|
| `ID` | string | 레코드 식별자 | 조인·추적 |
| `BaseLine` | number | 기저 심박수 | 초기 CTG 입력 |
| `Baseline_Variability` | string | 0 absent, 1 minimal, 2 moderate, 3 marked | 초기 CTG 입력 |
| `Acceleration` | string | 1 Yes, 2 No | 초기 CTG 입력 |
| `Early_deceleration` | string | 0 No, 1 Yes | 초기 CTG 입력 |
| `Late_deceleration` | string | 0 없음, 1 1회, 2 2회 이상 | 초기 CTG 입력 |
| `Variable_deceleration` | string | 0 없음, 1 1회, 2 2회 이상 | 초기 CTG 입력 |
| `Prolonged_deceleration` | string | 0 No, 1 Yes | 초기 CTG 입력 |
| `Sinosoical_pattern` | string | 0 No, 1 Yes | 초기 CTG 입력, 원본 철자 보존 |
| `CA` | string | 0 CA1, 1 CA2, 2 CA3 | 정답·검증 후보, 입력 사용은 별도 실험 |
| `Abnormality` | string | 이상 정보 | 정의 확인 전 입력 금지 |
| `Bbox` | array | 이상 시점 좌표 | 현재 MVP 미사용 |
| `Emergency` | string | 0 비응급, 1 응급 | 2단계 학습 목표 후보 |

AIHub 원본 호환 계층에서는 `BaseLine`, `Sinosoical_pattern` 같은 공개 표기를 보존한다. 내부 표준 스키마에서는 각각 `baseline`, `sinusoidal_pattern`처럼 일관된 이름으로 정규화하고 양방향 매핑을 테스트한다.

### 3.2 EMR 입력 후보

분만 전 또는 초기 관찰 시점에 실제로 알 수 있는지 검토할 주요 필드는 다음과 같다.

- 산모: 측정월, 생년월, 키, 체중, ABO/Rh, 임신 횟수, 출산 횟수, 수축기·이완기 혈압
- 산모 위험요인: 임신성 고혈압, 기존 고혈압, 임신성 당뇨, 당뇨, 전자간증·자간증
- 임신·태아: 임신 주수, 태아성장제한, 태반 합병증, 자궁경부 정보, 단태아·다태아

다음 필드는 출생·분만 결과 또는 사후 정보일 가능성이 높아 0~2단계 입력에서 기본적으로 차단한다.

- `Delivery`
- `FetalDistress`
- `Placenta.Weight`
- `Birth Date`
- `Sex`
- `Weight`, `Height`, `HC`
- `APGAR.1min`, `APGAR.5min`
- `UA.pH`, `UA.BE`, `UA.pO2`, `UA.pCO2`
- `NICU.Adm`, `Intubation`, `Jaundice`
- `prematurity`, `LBW`
- `Anomaly` 및 `Anomaly1`~`Anomaly8`
- `Emergency`와 합성 생성용 기대 결과 컬럼

`FetalDistress`, `Delivery`, 태아 성별처럼 측정 또는 기록 시점이 기관별로 다를 수 있는 필드는 실제 데이터의 작성 시점을 확인하기 전까지 보수적으로 차단한다.

## 4. 시간적 데이터 계약

각 특성에는 다음 중 하나의 가용 시점을 부여한다.

| 시점 | 설명 | 사용 단계 |
|---|---|---|
| `PRE_LABOR` | 분만 시작 또는 CTG 관찰 전에 확인 가능 | 0, 1, 2단계 |
| `EARLY_CTG` | 정의된 초기 CTG 관찰 구간 안에서 계산 | 1, 2단계 |
| `POST_WINDOW` | 초기 관찰 구간 이후에만 확인 가능 | 입력 금지 |
| `POST_DELIVERY` | 분만 또는 출생 이후 결과 | 입력 금지 |
| `TARGET` | 예측·검증 대상 | 입력 금지 |
| `UNKNOWN` | 기록 시점이 확인되지 않음 | 확인 전 입력 금지 |

모델 학습 전 특성 목록과 시점 목록을 대조해 `POST_WINDOW`, `POST_DELIVERY`, `TARGET`, `UNKNOWN`이 포함되면 실패하도록 한다. 환자 단위 식별자가 있으면 같은 산모 또는 태아가 학습·검증 세트에 동시에 들어가지 않도록 그룹 분할한다.

### 4.1 초기 CTG 관찰창

MVP의 기준시점과 관찰창은 다음과 같이 고정한다.

| 항목 | 계약 |
|---|---|
| 관찰 시작 `t0` | CTG 기록이 연속적으로 시작된 시각 |
| 초기 관찰창 | `[t0, t0 + 20분)`인 왼쪽 닫힘·오른쪽 열림 구간 |
| 예측 기준시점 | `t0 + 20분` |
| 최소 완전성 | 20분 전체가 관찰되었거나, 원천 데이터가 해당 구간의 요약임을 입증하는 출처 정보가 있어야 함 |
| 경계 처리 | 정확히 기준시점에 발생하거나 기록된 정보는 입력이 아니라 결과 구간에 속함 |

20분은 기능 시연을 위한 버전 `early-window-v1`의 운영상 기본값이며 임상 표준이나 처치 기준을 뜻하지 않는다. 실제 데이터에서 관찰 시작·종료 시각을 확인할 수 없으면 공개 CTG 요약 필드는 자동으로 `EARLY_CTG`가 되지 않는다. 입력 어댑터가 `window_start`, `window_end`, `window_complete`, `timing_source`를 확인한 경우에만 `EARLY_CTG`로 승격하고, 그 전에는 `UNKNOWN`으로 차단한다.

향후 실제 데이터 구조나 승인된 임상 근거에 따라 길이를 바꿀 때는 관찰창 버전, 합성 데이터, 모델과 결과 계약을 함께 올린다. 서로 다른 관찰창 버전으로 만든 데이터와 모델은 호환되지 않는 것으로 처리한다.

### 4.2 예측 목표

2단계의 표준 목표 이름은 `emergency_after_index`로 확정한다. 의미는 **예측 기준시점 직후부터 해당 분만 에피소드가 끝날 때까지 새로 확인된 응급 상태 여부**이며, 이진값 `0`과 `1`만 허용한다.

- 기준시점 이전에 이미 확인된 응급 상태는 예측 대상 모집단에서 제외하고 별도 상태 `not_eligible`로 처리한다.
- 사건 시각이나 분만 에피소드 종료를 확인할 수 없으면 라벨 상태를 `unresolved`로 두고 학습·평가에서 제외한다.
- 공식 `Emergency` 필드는 이름이 같다는 이유만으로 자동 매핑하지 않는다. 사건 정의와 기록 시점이 공식 설명서 또는 샘플로 확인된 경우에만 매핑한다.
- 현재 합성 데이터는 같은 의미의 `synthetic_emergency_after_index`를 생성한다. 이 값은 기능 시험용 목표이며 공식 `Emergency`나 실제 임상 사건을 재현한다고 주장하지 않는다.
- 모델 학습 시 목표값과 함께 `target_definition_version=emergency-after-index-v1`, 관찰창 버전과 생성 근거 버전을 저장한다.

고정 시간 예측 지평 대신 분만 에피소드 종료까지를 택한 이유는 현재 공개 정보만으로 30분·60분 등 특정 시간 내 사건을 재구성할 수 없기 때문이다. 실제 데이터에 사건 시각이 있으면 고정 지평 모델은 별도 목표 버전으로 추가하고 기존 결과와 섞지 않는다.

### 4.3 필드 계약과 검증 단계

원본 필드와 내부 필드를 한 계층에서 섞지 않는다. 입력 경계는 AIHub 공개 이름을 보존하고, 내부에서는 `snake_case` 이름과 명시적 타입을 사용한다. 필드별 계약은 `configs/field-contract.yaml`을 단일 실행 기준으로 삼으며 최소한 원본명, 내부명, 타입, 단위, 코드 집합, 결측 표현, 가용 시점, 역할과 출처 상태를 가진다.

검증은 다음 세 단계로 나눈다.

1. **구조 검증**: 필드 존재 여부, JSON 타입, 파싱 가능 여부를 확인한다.
2. **의미 검증**: 공식 코드와 단위가 확인된 필드만 코드·범위 검사를 통과시킨다. 정의가 불명확한 값은 원문을 보존하되 `semantic_status=unresolved`로 둔다.
3. **모델 적격성 검증**: 시점, 출처 정보, 목표·사후 여부를 확인한다. `UNKNOWN`, 결과 변수, 식별자와 생성 메타데이터는 모델 입력에서 실패시킨다.

필수 여부도 단계별로 구분한다. 식별자와 출처 정보는 처리 계약상 필수이고, 임상 입력의 누락은 곧바로 전체 입력 오류로 만들지 않는다. 대신 해당 단계의 완전성을 낮추고 필요한 최소 입력이 없으면 그 단계만 `insufficient_data`로 반환한다. `9999`, 빈 문자열과 명시적 미상 코드는 정규화 후 `null`이며 실제 수치나 범주로 사용하지 않는다.

### 4.4 코드와 범위를 모를 때의 기본 동작

- 공식 코드북이 확인된 열은 허용 목록 방식으로 검사한다.
- 코드북이 확인되지 않은 EMR 범주형 열은 원문 보존과 합성 전용 내부값을 분리한다. 원문 값은 규칙이나 모델 특성으로 사용하지 않는다.
- 임상 범위가 승인되지 않은 연속형 열은 타입·단위·수학적 제약만 오류로 검사하고, 비정상적으로 보이는 값은 삭제하지 않고 경고로 남긴다.
- 입력에 정의되지 않은 필드는 기본적으로 보존하지 않으며 오류의 필드명과 지원 계약 버전을 반환한다. 향후 호환성이 필요한 어댑터에서만 별도 확장 영역으로 격리한다.
- 정규화는 새 객체를 만들며 원본 입력을 변경하지 않는다.

## 5. 합성 데이터 근거 수집

### 5.1 수집 대상

대규모 웹 문서를 그대로 학습 데이터로 크롤링하지 않는다. 다음 출처에서 변수 생성에 필요한 수치와 관계만 구조화해 수집한다.

1. AIHub 공식 데이터 설명서와 공개 집계
2. ACOG, NICHD 등 전문기관의 FHR 정의·분류 기준
3. WHO, 질병관리청, 통계청 등 공식 산모·신생아 통계
4. PubMed에 등재된 원저·체계적 문헌고찰
5. 라이선스와 이용 조건이 명확한 공개 데이터셋의 데이터 사전·집계

검색 결과나 블로그의 요약만으로 임상 임계값을 확정하지 않는다. 원문 제목, 기관, URL, 발행일, 적용 변수와 사용한 값을 근거 목록에 기록한다. 개인별 사례, 환자 서술, 원문 표의 대량 복제는 수집하지 않는다.

### 5.2 근거 레지스트리

합성 규칙은 최소한 다음 정보를 가져야 한다.

```text
rule_id
variable
source_id
source_type
population
value_or_relationship
unit
applicability
status
notes
```

`status`는 `proposed`, `reviewed`, `approved`, `rejected` 중 하나로 관리한다. 실제 생성기는 `approved` 규칙만 기본 프로필에 사용한다.

## 6. 합성 데이터 생성 전략

### 6.1 두 가지 프로필

- `distribution` 프로필: AIHub 공개 집계와 승인된 외부 분포를 최대한 재현해 배치 처리와 데이터 파이프라인을 시험한다.
- `coverage` 프로필: 정상, 경계, 고위험, 규칙 충돌, 결측과 오류 사례를 의도적으로 충분히 포함해 모든 기능 경로를 시험한다.

두 프로필을 섞어 하나의 성능 데이터처럼 사용하지 않는다. 모든 행에 `synthetic_profile`, `scenario_type`, `generator_version`, `generation_seed`를 기록하되 모델 입력에서는 제외한다.

### 6.2 계층적 생성 순서

1. 산모·임신 시나리오를 선택한다.
2. 산모 연령, 임신·출산력과 기저 위험요인을 조건부로 생성한다.
3. 임신 주수, 태아 수와 태아 성장 관련 변수를 생성한다.
4. 시나리오에 조건부인 초기 CTG 특징을 생성한다.
5. 승인된 임상 규칙으로 기대 CA 또는 규칙 판정값을 만든다.
6. EMR 위험, CTG 위험, 상호작용과 확률 잡음을 조합해 합성 `Emergency` 발생 확률을 만든다.
7. 결과 변수를 생성한 후 사후 변수는 결과에 조건부로 별도 생성한다.
8. 일부 행에 계획된 결측, 미상 코드와 경계값을 주입한다.

모든 열을 독립 난수로 뽑지 않는다. 예를 들어 임신 주수와 출생체중, 고혈압과 전자간증, CTG 변이도와 감속, CA와 응급 라벨은 승인된 관계에 따라 조건부로 생성한다.

### 6.3 합성 라벨

합성 `Emergency`는 다음 개념 구조를 사용한다.

```text
logit = intercept
      + maternal_risk_component
      + pregnancy_risk_component
      + early_ctg_component
      + approved_interactions
      + stochastic_noise
probability = sigmoid(logit)
Emergency ~ Bernoulli(probability)
```

계수와 절편은 실제 임상 효과 크기가 아니라 생성기 내부의 시나리오 강도를 나타낸다. 각 계수는 근거 또는 시연 목적, 기대 방향과 버전을 기록한다. 모델이 생성 공식을 완벽히 복제하지 않도록 확률 잡음과 겹치는 위험 분포를 포함하지만, 이를 실제 세계의 불확실성으로 해석하지 않는다.

## 7. 규모와 데이터 세트 분리

생성기는 동일한 스키마로 다음 산출물을 만들 수 있어야 한다.

| 산출물 | 권장 규모 | 목적 |
|---|---:|---|
| 규칙 단위 사례 | 100~500 | 경계값과 규칙 우선순위 테스트 |
| 개발 데이터 | 5,000~10,000 | 파이프라인·학습·UI 개발 |
| 대규모 시연 데이터 | 50,000 이상 | 처리량, 재현성, 배치 실행 시연 |
| 대표 데모 사례 | 5~20 | 정상·경계·고위험·결측 화면 시연 |

학습·검증·테스트 분할은 생성 후에 하며 합성 환자 그룹을 보존한다. 규칙 단위 사례와 대표 데모 사례는 ML 성능 집계에서 제외한다.

## 8. 데이터 품질 검사

생성 완료 조건은 행 개수가 아니라 다음 검사를 모두 통과하는 것이다.

- 스키마: 필수 열, 타입, 코드, 단위와 식별자 유일성
- 범위: 생리적으로 불가능하거나 사양 밖의 값이 없음
- 논리: 임신 주수·태아 정보·결과 변수 사이의 정의된 제약 충족
- 분포: 목표 분포와 실제 생성 분포의 차이가 허용오차 안에 있음
- 관계: 승인된 조건부 관계의 방향이 생성 결과에 나타남
- 범위 커버리지: 정상·경계·고위험·결측·오류 경로가 모두 존재
- 누수: 금지 열과 생성 메타데이터가 모델 특성에 없음
- 재현성: 같은 시드·구성·버전으로 동일 체크섬 산출
- 다양성: 중복 행과 사실상 동일한 복제 사례가 허용 기준 이하

분포 허용오차와 중복 허용 기준은 생성기 구현 전에 테스트 가능한 수치로 확정한다.

## 9. 산출물과 추적성

합성 데이터 생성 시 다음을 함께 저장한다.

- 데이터 파일
- 스키마 버전
- 생성 구성과 난수 시드
- 생성기 코드 버전
- 사용한 근거 규칙 식별자 목록
- 분포·논리·누수 검사 보고서
- 파일 체크섬

대용량 생성 파일과 학습 모델은 기본적으로 생성물로 취급하고 저장소 추적 여부를 구현 단계에서 `.gitignore` 정책과 함께 확정한다. 대표 소형 fixture만 테스트 목적으로 추적하는 방식을 우선한다.

## 10. 알려진 한계

- 공개된 주변분포만으로 실제 변수의 결합분포를 복원할 수 없다.
- 문헌의 대상 인구와 AIHub 참여병원 환자군은 다를 수 있다.
- 합성 응급 라벨은 실제 임상 사건 정의와 발생 과정을 재현하지 않는다.
- 합성 데이터에서 좋은 모델 성능은 생성 규칙 학습 능력만 보여준다.
- 실제 데이터의 기록 시점, 반복 측정 구조와 결측 메커니즘은 샘플 확인 전 알 수 없다.

따라서 합성 데이터의 역할은 기능, 계약, 예외 처리와 처리량 검증으로 제한한다.
