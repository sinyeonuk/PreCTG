# PreCTG 데모 및 인수 안내

이 문서는 팀원이 개발자 도움 없이 로컬 MVP를 실행하고 발표하며, 본선에서 실제 데이터로 전환할 지점을 안내합니다.

## 빠른 데모

개발 환경을 설치한 뒤 저장소 루트에서 다음 명령을 실행한다.

```powershell
streamlit run app/streamlit_app.py
```

1. `대표 사례`에서 기본·분만 전 관찰·초기 CTG 관찰·복합·결측·규칙 충돌 중 하나를 선택한다.
2. `입력 확인`에서 분만 전 정보와 초기 CTG 값을 확인하거나 수정한다.
3. `분석 실행`을 누른다. 첫 실행에서는 로컬 합성 데이터로 LightGBM을 준비하므로 이후 실행보다 조금 오래 걸릴 수 있다.
4. 통합 신호, 0·1·2단계 변화, 판단 근거와 입력 완전성을 확인한다. 모델 내부 분석값은 `모델 분석 상세`에서 확인한다.
5. 필요하면 `결과 JSON 저장`으로 같은 결과 계약을 저장한다.

모든 화면은 인터넷 없이 동작하며 실제 의료정보를 입력하지 않는다.

## 발표 권장 순서

- 기본 사례: 3단계 결과와 설명 구조를 짧게 소개한다.
- 복합 관찰 사례: 정보가 누적될 때 단계 신호가 어떻게 달라지는지 보여준다.
- 결측 사례: 부족한 입력을 낮은 위험으로 오해하지 않고 별도 상태로 처리함을 보여준다.
- 모델 없음 CLI: `prectg predict --input data/fixtures/minimal-synthetic-input.json`으로 규칙 결과는 보존하고 ML 확률은 만들지 않음을 보여준다.

화면의 등급과 확률은 기능 시연용 합성 결과이며 실제 성능 수치로 소개하지 않는다.

## 검증 기록

기준 환경은 Windows 10 계열, Python 3.11.15, Intel64 Family 6 Model 140 CPU다. 2026-08-14에 고정 시드 `20260814`로 측정했다.

| 작업 | 측정값 | 기준 | 결과 |
|---|---:|---:|---|
| 50,000건 생성과 품질 검사 | 1.730초 | 60초 이내 | 통과 |
| 50,000건 LightGBM 학습 | 1.560초 | 5분 이내 | 통과 |
| 50,000건 배치 추론 | 0.609초 | 15초 이내 | 통과 |
| 준비 후 단일 사례 추론 | 0.004초 | 1초 이내 | 통과 |

- 레코드 식별자 중복 0건, 정의된 스키마·논리 위반 0건
- 학습·검증 산모 그룹 중복 0건
- 공개 집계 검사 9개 항목이 모두 ±1%p 이내이며 최소 시나리오 건수는 2,525건
- 데이터 체크섬: `f3104897e513f63b7905bef43731a716f92fa994b40274f009c9ce746f5684e0`
- 합성 AUC는 디버깅 정보일 뿐 제안서의 모델 성능 근거로 사용하지 않음

재측정은 `python scripts/benchmark.py`로 수행한다. 환경이 달라지면 결과 JSON의 환경 정보와 시간을 함께 보관한다.

Streamlit 첫 화면은 같은 환경의 로컬 브라우저에서 약 3.5초 안에 표시됐다. 1280px·1024px·768px·390px 화면폭에서 가로 스크롤이 없음을 확인했고, 기본·복합 고위험·결측·모델 없음 흐름을 실행했다. 결과 JSON 다운로드가 시작되고 브라우저 콘솔 오류가 없음을 확인했다. 브라우저가 불러온 HTTP 자산 52개는 모두 `localhost`였고 Pretendard는 데이터 URL로 포함됐다.

별도의 Python 3.11.15 가상환경을 새로 만든 뒤 `requirements-dev.txt` 설치, `prectg status`와 전체 테스트 46개를 다시 실행해 README 설치 절차가 기존 개발 환경에 의존하지 않음을 확인했다. 시스템 기본 Python이 3.10 이하인 경우에는 의존성 설치 전에 3.11 이상 인터프리터를 선택해야 한다.

검증 캡처는 로컬 `outputs/demo-captures/`에 `normal.png`, `high.png`, `missing.png`, `model-unavailable.png`로 생성했다. 이 디렉토리는 실행 산출물이므로 Git에 넣지 않는다. 다시 만들 때는 각 대표 사례를 분석한 뒤 같은 이름으로 현재 화면을 저장한다.

## 팀 인수 확인

기술 구현 완료 이후의 팀 인수 결과는 [완료 감사와 팀 확인표](completion-audit.md)에 기록한다. 개발자가 먼저 설명하지 않은 상태에서 팀원이 `빠른 데모` 절차를 수행하고, 두 명이 화면·JSON의 비임상용 문구를 검토한다. 이 절차는 사용자와 팀의 후속 확인이며 Codex의 구현 완료 조건은 아니다.

## 본선 실제 데이터 전환

1. 공식 설명서와 샘플에서 레코드 단위, 반복 측정 구조, 코드와 단위를 확인한다.
2. 공식 `Emergency`의 사건 정의와 시점을 확인해 현재 목표에 매핑할 수 있는지 결정한다.
3. 관찰 시작·종료 시각으로 초기 20분 창의 출처를 검증하거나 새 관찰창 버전을 정의한다.
4. 실제 산모·태아 그룹 키를 정하고 동일 그룹이 분할을 넘지 않는지 검사한다.
5. `configs/field-contract.yaml`을 갱신하고 입력 fixture와 계약 테스트를 먼저 수정한다.
6. 누수 검사 후 실제 데이터용 모델을 새 번들 버전으로 재학습한다.
7. 합성 모델과 실제 데이터 모델의 산출물·수치·화면 캡처를 섞지 않는다.
8. 반출 가능한 집계와 결과 형식을 안심존 규정에 맞춰 별도로 검토한다.

## 알려진 제한

- 승인된 임상 규칙은 아직 없어 임상 모드는 결과 없음으로 동작한다.
- CTG 원본 이미지·연속 파형 특징 추출과 병원 시스템 연동은 범위 밖이다.
- 브라우저 화면은 경진대회 시연용 수준이며 의료기기나 운영 서비스가 아니다.
